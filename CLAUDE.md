# Candidate Onboarding: project guide

Expo SDK 58 / React Native 0.88 app: a candidate signs in, completes a 5-step document wizard, and submits through an offline outbox to an in-app mock backend. Read [README.md](README.md) for the product view and the known limitations.

## Commands

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # expo lint
npm test            # jest (jest-expo preset)
npx expo export --platform android --output-dir "$TMP/bx"   # proves Metro resolves every module (tsc does not)
eas build -p android --profile preview --non-interactive --no-wait
```

All three of typecheck, lint and test must pass before a commit. CI runs the same on Node 24 with `npm ci`.

## Architecture rules

- `src/domain/types.ts`: plain types only, no imports from the rest of the app.
- `src/api`: `ApiClient` is the contract; `src/api/index.ts` is the only place that picks `MockApiClient`. Screens never import `MockApiClient`.
- **Writes go through the outbox, never straight to the API.** Screens call `useOutboxStore.getState().enqueue()` then `kick()`. TanStack Query is for reads only.
- Persisted state lives in Zustand stores in `src/stores/` with `persist` + `persistStorage` (AsyncStorage). Drafts are keyed by Firebase `uid`.
- Routes live in `src/app/`; non-route code stays outside it. Auth guards are `Redirect`s in `(auth)/_layout.tsx` and `(app)/_layout.tsx`.
- Picked or captured files must go through `src/lib/files.ts` (resize, copy into `Paths.document/onboarding/<uid>/`). Never store a cache URI in a draft.

## Outbox invariants (do not break)

- `runOutbox()` is single-flight; keep the module-level lock.
- Idempotency keys: submit uses `item.idempotencyKey`, each upload uses `${idempotencyKey}:${kind}`. A replay after a crash must reuse them.
- Error policy lives in the pure `failurePatch()`: `NetworkError` → `pending`, attempts unchanged; 5xx → backoff `BACKOFF_MS`, `failed` at `MAX_ATTEMPTS`; 4xx → `failed`.
- `recoverInFlight()` runs on rehydrate. Removing it makes the crash-recovery test fail, by design.
- The backoff timer in `useOutboxTriggers` only arms for *future* deadlines. Arming it for items already due would spin in a 0 ms loop while offline.

## Persisted state changes

Every store declares `version: 1` and has no `migrate` yet. Changing the shape of `Draft`, `OutboxItem` or `DevSettings` requires bumping `version`, adding `migrate`, and a test that hydrates the previous shape.

## Gotchas found in this codebase

- **Firebase RN persistence types.** `firebase/auth` only ships web typings; `getReactNativePersistence` exists at runtime (Metro resolves `@firebase/auth/dist/rn`). The declaration is in `src/types/firebase-auth.d.ts`. Do not import from `@firebase/auth` directly.
- **Google Sign-In crashes Expo Go if imported at top level.** It is `require`d lazily in `src/lib/firebase/auth.ts` behind `isGoogleSignInAvailable`. Keep it that way.
- **React Compiler is on** (`experiments.reactCompiler`). Use RHF `subscribe()` instead of `watch()`, no ref reads during render, no `Date.now()` in render (use a lazy `useState` initialiser).
- **expo-file-system** uses the `File` / `Directory` / `Paths` API. `copy`/`move` are async, `delete`/`create` are sync. The legacy function API is not used here.
- **expo-image-manipulator** uses `ImageManipulator.manipulate(uri).resize(...).renderAsync()` then `saveAsync()`.
- **TypeScript 6** does not pick up `@types/jest` automatically; `tsconfig.json` sets `"types": ["jest"]`.
- **React Native Testing Library v14**: `renderHook`, `act` and `unmount` are async and must be awaited.
- **Lockfile**: generated by npm 11 (Node 24). If `npm ci` fails in CI, regenerate with `npm install --package-lock-only` on Node 24.
- **EAS status**: `eas build:view <id> --json` failed to parse in scripts; `eas build:list --limit 1 --non-interactive` shows `Status` and `Application Archive URL` reliably.

## Testing conventions

Every test carries a comment card: `protects=… ; fails_when=… ; no_claim=…`. Keep it on new tests. Tests use injected deps (`MockApiClient({ getSettings, isOnline, sleep })`) instead of real timers or network. AsyncStorage, NetInfo and expo-crypto are mocked in `jest.setup.ts`.

## Firebase / EAS

- Firebase project `bowery-demo`, Android package `com.bowery.onboardingdemo`. Client config is committed on purpose (see README).
- Google Sign-In depends on the EAS keystore SHA-1 being registered in Firebase. A new keystore means a new SHA-1 and a new `google-services.json`.
- EAS project `@awsthyn/candidate-onboarding-demo`; `preview` profile builds an APK.
